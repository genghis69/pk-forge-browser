🧩 Ressources Android AAPT2 et APK signé

Chaîne WebAssembly : AAPT2 compile les layouts, thèmes, couleurs, drawables et le manifeste en véritables ressources Android ; Kotlin et D8 produisent les DEX, puis Google Pack assemble et signe l’APK. Le projet doit passer chaque validation.

Ordre : 1. Préparer les ressources, 2. recompiler Kotlin avec le vrai R, 3. générer le DEX runtime, 4. assembler l’APK. Les anciens DEX de diagnostic, construits avec R temporaire, sont refusés.

Ressources en attente : lance « 1. Compiler ressources + R réels ». AAPT2 WebAssembly prend en charge les fichiers XML Android ; chaque erreur éventuelle sera détaillée.

🛠 Compilation Kotlin Android (laboratoire, JAR puis DEX)

ELM327 et projets compatibles : compile TOUS les fichiers .kt de src/main ensemble avec SDK Android 36, Kotlin 2.2.20, AndroidX Core et USB Serial. Les bibliothèques sont téléchargées dans Chrome et mises en mémoire pour CheerpJ. Aucun fichier du projet n’est envoyé à un serveur.

Les deux étapes sont indépendantes : dès que Kotlin a créé le JAR, télécharge-le immédiatement. Lance ensuite D8 uniquement avec le bouton 2. Une conversion D8 lente ou bloquée ne fait plus recommencer Kotlin.

Important : lance d’abord « Compiler ressources + R réels » : la recompilation Kotlin doit ensuite utiliser les identifiants R issus d’AAPT2. Le R temporaire n’est valable que pour le diagnostic et ne permet pas d’assembler l’APK final.

Étape suivante : DEX avec bibliothèques d’exécution

Pour réduire les risques de contention des threads Java sous CheerpJ, teste le réglage 1 thread. Ce n’est pas une garantie de rapidité. L'opération sur 21 JAR peut prendre plusieurs minutes ; les résultats du JAR Kotlin restent téléchargeables.

Intégrer le code ELM327, Kotlin Stdlib, AndroidX, USB Serial et leurs dépendances dans D8. Un fichier ZIP contenant le ou les DEX sera disponible. Attention : le DEX doit être recompilé après AAPT2 avec les vrais identifiants R ; cette étape seule ne constitue pas encore un APK installable.
